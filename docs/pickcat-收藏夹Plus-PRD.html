PickScribe 收藏夹 Plus（带分组功能的收藏增强模块）

版本 v0.3（已纳入两轮评审决策） 日期 2026-10-18 归属：PickScribe 扩展（Chrome / Edge · Manifest V3） 目标站点：pickcat.dao3.fun P0 功能 43 项 / P1 功能 4 项

背景与目标

Pickcat 站点自带的收藏能力是一条平铺的收藏列表：用户点击收藏按钮后，帖子进入收藏列表，只能按收藏时间浏览，不能分组、不能检索、不能备注。收藏数量增长后，用户重新找到某个收藏的成本随数量线性上升，收藏逐渐从"可复用的资料库"退化为"一次性动作"。

问题链路

站点收藏夹不支持分组与检索（现象） → 收藏量大的用户无法按主题/项目/作者复用收藏内容（受影响用户与场景） → 本模块为收藏夹补充分组、标签、备注与检索能力，并把分组数据与站点收藏保持同步（产品决策） → 用户可在 3 步内把一个帖子存入指定分组，并能在任意时刻用关键词或分组定位到它（可观察结果）。

目标（定性、可观察）

  • 用户可在收藏动作发生的当下，把帖子归入一个或多个自定义分组，无需事后逐个搬运。
  • 用户可通过分组、标签、关键词、备注任意组合缩小范围，并在同一视图内完成浏览、排序与整理。
  • 收藏数据不因站点侧变动（取消收藏、帖子被删除、帖子转为私密）而与插件视图产生静默不一致——不一致必须可见、可选择处置。
  • 分组、标签、备注默认只保存在用户本机；除站点自身的收藏请求外不产生对外数据请求。

前提 目标站点为 https://pickcat.dao3.fun/（含旧域名 cdsq.dao3.fun）；收藏对象为站内帖子。本模块归属 PickScribe 扩展，与既有「富文本编辑器」「AI 助手」共用同一扩展外壳与弹窗入口，作为其中的收藏增强模块交付，不新建独立项目。站点自带收藏夹为单一平铺列表，不提供分组能力。

已确认决策
① 收藏项允许同时归属多个分组（多对多），计数与移出规则按多归属口径执行；
② 管理主入口为点击扩展图标弹出的弹窗，不使用站点页面或独立全屏页作为默认工作台；
③ 形态为 Chromium Manifest V3 扩展，仅需支持 Chrome 与 Edge，不做 Firefox 适配；
④ 站点收藏夹可完整读取，且取消收藏可被感知 → SYN-01 / SYN-02 走自动同步；
⑤ 社区内已有账号体系 → P1 云同步（SYN-06）成立，以站点登录态为准；
⑥ 帖子被设为私密即判定为"已失效"；
⑦ 收藏数据沿用站点收藏夹作为唯一数据源，插件不另建收藏体系；"导出收藏夹"（含分组、标签、备注）为保留能力。

范围与优先级

P0 定义为"收藏夹 Plus 的最小完整闭环"：收藏 → 归组 → 检索 → 整理 → 数据可迁移。任何 P0 缺口都会导致闭环断裂，因此 P0 必须整组交付。

优先级范围说明
P0分组体系、收藏归组、浏览检索、信息与备注、批量整理、收藏夹导出与导入、入口与呈现、基础设置构成完整可用闭环：用户能建组、收藏时归组、按组与关键词找到它、批量整理、并把收藏夹导出备份
P1嵌套分组、智能分组、标签推荐、云同步跨设备在 P0 闭环稳定且数据一致性规则验证通过后再评估；社区账号已确认存在，云同步不再受账号缺失限制
不做修改站点自身收藏数据、代站点提交非收藏类写操作、对站点内容做二次发布、抓取非收藏范围内的用户数据属于越界写操作或越界数据范围，超出"收藏增强"的产品边界

最小完整旅程（P0）

  1. 进入条件：用户已登录 Pickcat（社区账号），PickScribe 扩展已安装并启用收藏增强模块。
  2. P0 动作：在帖子页点击收藏 → 面板中勾选分组 → 确认；随后在弹窗中用分组或关键词定位该帖 → 加备注/标签 → 批量调整或删除。
  3. 完成证据：帖子页收藏按钮呈现"已收藏 · 已归入 N 个分组"；弹窗内对应分组计数 +1，帖子出现在该分组视图内。
  4. 恢复路径：若归组失败（面板被关闭、站点请求失败），帖子仍存在于"未分组收集箱"，用户可在弹窗中重新归组，不丢失收藏动作；弹窗中途关闭不影响已提交结果。
  5. P1 支撑：嵌套分组、智能分组、标签推荐、云同步。

产品模型与核心流程

对象模型

对象定义关键属性
收藏项 FavoriteItem一条被收藏的帖子记录，以站点帖子 ID 为唯一标识帖子ID、标题、作者、封面、原帖链接、类型、收藏时间、失效状态、备注、标签集合
分组 Group用户自定义的集合容器，用于组织收藏项分组ID、名称、图标、颜色、排序位、创建时间、（P1）父分组
归组关系 Membership收藏项与分组的多对多关系（一个收藏项可属于多个分组）收藏项ID、分组ID、归组时间、手动/自动来源
标签 Tag跨分组的扁平标记，用于横向筛选标签名、使用次数
未分组收集箱 Inbox系统内置、不可删除的虚拟分组，承接所有未显式归组的收藏项实时计数，成员 = 收藏项集合 − 已归组集合

核心流程

收藏动作发生 → 扩展在帖子页捕获收藏意图 → 用户选择分组（可跳过）→ 扩展提交站点收藏请求并写入本地归组关系 → 弹窗内各视图与计数同步刷新。其中站点收藏与分组归组是两个可独立成败的步骤：站点收藏失败时归组关系不写入；归组未选择时站点收藏照常写入并落入未分组收集箱。

数据源单一：站点收藏夹是收藏项的唯一来源，插件只在本地附加"分组 / 标签 / 备注"三样站点没有的数据；插件不维护独立收藏体系，也不改写站点侧的收藏内容。

4.1 分组体系（GRP-01 ~ GRP-07）

目的：让用户用自己熟悉的主题维度组织收藏，替代按时间平铺。触发：弹窗分组区新建入口，或收藏面板内联新建。

处理规则

规则定义
名称唯一性同一层级内分组名去空格后不区分大小写唯一；重名时复用已有分组并提示"已加入现有分组"，不静默创建副本
名称约束长度 1–24 字符，首尾空格自动去除，仅空格视为空名并拒绝
删除分组必须选择成员去向：移入未分组收集箱（默认）或 移入指定分组；删除为二次确认动作，取消则不改动任何数据
排序拖拽调整顺序并立即持久化；未分组收集箱与"全部收藏"为系统视图，固定置顶、不可拖拽、不可删除
图标与颜色从预设集合选择；未选择时按名称哈希分配稳定默认色，保证列表可辨识且不随刷新变化
置顶与折叠置顶分组固定在分组区顶部；折叠状态仅影响展示，不影响计数与筛选结果
嵌套（P1）最多两层；父分组计数包含子分组内容，但父分组在视图中展示为"直接隶属成员 + 子分组入口"两段
智能分组（P1）条件命中后新收藏自动归入；已归入项不因条件失效被自动移出，避免用户手动整理结果被覆盖

结果与状态变化

新建/重命名/删除后，分组切换条、分组计数、弹窗内筛选结果与收藏面板中的可选分组列表在同一时刻更新，无延迟残留。

异常

  • 重名：给出已有分组指引，用户可选择直接加入或改名。
  • 空名/超长：内联提示，保存按钮不可用。
  • 删除进行中：成员迁移失败则不执行删除，保持原状态并提示重试。

4.2 收藏与归组（COL-01 ~ COL-07）

目的：把"分组"从收藏之后的事后整理，变成收藏当下的顺手动作。触发：用户在帖子卡片或详情页点击收藏。

处理规则

规则定义
两步解耦"站点收藏"与"归组关系写入"相互独立：站点收藏失败则归组关系不写入；归组失败则收藏仍成功并进入未分组收集箱
面板默认态按 SET-01 配置呈现：默认展开选择面板 / 直接进最近使用分组 / 直接进未分组收集箱
多归属勾选分组即新增归属，取消勾选仅移出该分组；不提供"整体替换"的隐式行为，避免误伤其他分组
已收藏状态已收藏帖子再次点击收藏即打开面板，按钮文案为"已收藏 · 已归入 N 个分组"，N 实时对应归组数量
取消收藏联动按 SET-02：同步移除归组关系（默认）／保留归组关系但标记为已取消收藏／仅提示不处理
提交时机面板确认即提交，回车等同确认，Esc 等同取消且不产生任何写入

4.3 浏览与检索（BRW-01 ~ BRW-06）

目的：在一个视图内完成"找得到 + 看得清"，减少在站点与弹窗之间的往返。触发：打开弹窗，或点击分组/输入搜索词/点击标签。

处理规则

  • 弹窗内布局：自上而下为"工具栏（搜索 + 失效筛选）→ 分组切换条 → 内容区 → 底部状态栏"，横向占满弹窗宽度。分组切换条以横向可滚动的方式容纳全部分组，不采用左右双栏——弹窗宽度下双栏会把内容区压到无法容纳卡片网格。Chrome / Edge 弹窗宽度上限约 800px，因此以 790px 为设计基准，并对更窄的窗口向下自适应。
  • 筛选状态持久化：弹窗关闭即销毁页面，因此当前分组、搜索词、标签、失效筛选与内容区滚动位置必须保存，并在下次打开弹窗时恢复；用户主动点击"全部收藏"或清空筛选时才重置。
  • 内容区滚动：滚动发生在内容区内部，工具栏、分组切换条与底部状态栏固定不滚动，保证切换分组时搜索与筛选入口始终可见。
  • 过滤取交集：分组条件 × 搜索词 × 标签条件三者同时生效，结果需同时满足；"全部收藏"与"未分组收集箱"可与搜索、标签叠加。
  • 搜索范围：标题、作者、备注、标签名；大小写不敏感；连续输入即时过滤，不要求回车。
  • 排序默认：按收藏时间倒序；手动拖拽排序仅在该分组内生效，切换到其他分组不串用。
  • 标签来源：标签栏只展示当前结果集中实际出现的标签，避免出现"选了标签结果为空"的无效组合。
  • 展示密度：网格视图展示封面 + 标题 + 归属；列表视图展示标题、作者、时间、标签、备注摘要，用于快速扫读。
  • 快速预览：悬浮卡片在 0.3 秒内出现，仅读取已有本地元数据，不发起新请求。
  • 失效项呈现：失效项默认仍展示在结果中，但带明确标记，并可被"仅看失效"条件单独筛出。

4.4 收藏项信息与备注（ITM-01 ~ ITM-06）

目的：让收藏项脱离原帖也能被理解——标题可读、有备注、有标签、能判断是否还有效。触发：收藏动作发生时自动抓取；用户打开详情或编辑时手动修改。

字段来源规则
帖子 ID自动唯一标识，不可编辑；后续所有判重、同步、导入均以此为准
标题自动 + 可改抓取失败时以"未命名帖子 · 收藏时间"占位，并在项上提示可手动补全
作者自动 + 可改用于搜索与排序；缺失时归入"未知作者"
封面自动 + 可改抓取失败或与内容不符时允许替换；不可用封面以占位底色呈现
原帖链接自动点击打开原帖；失效项仍保留链接，便于用户自行确认
类型自动站点帖子类型字段；无类型信息时留空，不猜测
收藏时间自动以本地首次收藏时刻记录，后续重复收藏不覆盖
备注手动单条上限 500 字；参与搜索；仅在本地保存
标签手动（P1 可推荐）单条上限 10 个；标签名 1–16 字；重命名标签为全局生效，批量生效前需确认影响条数
失效状态自动取值：正常 / 待确认 / 已失效；帖子被设为私密即判为"已失效"；仅"已失效"参与"仅看失效"筛选与批量清理

异常：元数据抓取失败不阻塞收藏；备注与标签超过长度上限时截断并提示；失效为"待确认"时不参与批量清理，避免误删。

4.5 批量整理与清理（ORG-01 ~ ORG-05）

目的：让历史积压的未分组收藏一次性变得可用。触发：用户进入未分组收集箱或多选后出现批量操作条。

能力规则
多选Ctrl 单击追加、Shift 单击区间选择；进入多选后按钮变为"选择/取消"；Esc 退出多选并清空选择
批量归组批量"加入分组"为并集操作；批量"从当前分组移出"仅移出当前分组，不影响其他归属
重复合并同一帖子 ID 存在多条记录时提示合并；合并结果为一条记录，归组取并集，备注保留非空且较新的一条
批量移除默认仅从插件移除；若同时取消站点收藏，须在确认框中显式勾选并显示影响条数
失效清理批量清理前展示"已失效 N 条 / 待确认 M 条"，待确认项不默认勾选
操作可逆批量操作完成后 5 秒内提供撤销入口；超时后需通过导入已导出数据恢复

4.6 同步与数据（SYN-01 ~ SYN-06）

目的：保证插件视图与站点真实收藏不长期背离，并让用户的收藏夹数据可带走。

同步处理规则

  • 同步能力：站点收藏夹可完整读回（已确认），因此自动同步为默认能力：安装后首次做一次只读探测加以确认；若某次读取失败（登录态失效、接口变更），临时降级为"手动导入 / 单条补录"并提示原因，恢复后自动回到自动同步。
差异类型默认处置可选处置
站点有、插件无导入并进入未分组收集箱忽略本次导入
插件有、站点无保留记录并标记"站点已取消收藏"移除归组关系 / 直接移除记录（需确认）
两边都有但元数据不同以站点信息更新标题、作者、类型；覆盖用户已手动修改的字段需先确认保留本地手动值
  • 同步触发：扩展启动时、用户手动点击同步、弹窗打开且距上次同步超过设定间隔；同步为只读拉取，不改写站点数据。
  • 导出收藏夹：导出分组结构（含顺序、图标、颜色）、收藏项元数据、归组关系、标签、备注、收藏时间。JSON 为完整备份，CSV 保留分组列为多值字段，Markdown 用于人读浏览。导出的是"站点收藏 + 本地分组信息"的合成结果，不改变站点侧数据。
  • 导入合并：以帖子 ID 判重；分组按名称匹配，不存在则创建。
  • 数据清理：清空需输入确认词；明确告知"仅清除本地分组与备注，站点收藏不受影响"。
  • 云同步（P1）：社区已有账号体系，因此跨设备同步成立：以站点登录态为准，未登录时隐藏所有同步入口而非置灰，避免产生无法完成的引导。

共享规则与异常

计数规则（全局唯一口径）

  • 分组计数 = 该分组内收藏项条数（含已失效项，含已取消站点收藏但保留的项）。
  • 全部收藏计数 = 去重后的收藏项条数，不等于各分组计数之和，因为存在多分组归属。
  • 未分组收集箱计数 = 全部收藏计数 − 至少归属一个分组的收藏项数。
  • 新分组计数从 0 开始；删除分组后，其余分组与未分组收集箱计数立即重算。

状态与生命周期

状态进入条件可执行 / 不可执行
正常帖子可访问且未被取消收藏可归组、可编辑、可打开原帖
已取消收藏（站点侧）站点返回该帖未收藏可保留、可重新收藏、可移除记录；不可再向站点重复提交取消
待确认检查请求超时或返回不确定结果不参与批量清理；可手动重试检查
已失效帖子不存在、不可访问，或被设为私密可批量清理；保留链接与备注直到用户清理

权限与数据边界

  • 所有分组、标签、备注、归组关系均为单用户本地数据，仅该用户可见，不提供站内他人查看入口。
  • 扩展仅读写当前登录用户自己的收藏数据，不读取、不推断其他用户的信息。
  • 任何向站点发起的写操作仅限"收藏 / 取消收藏"，其余一律只读。
  • 扩展只需要站点域访问与本地存储能力，不申请与站点通信无关的主机权限；除与站点的必要通信外不发起外部请求。
  • 卸载或清空数据即不可恢复，因此导出入口需与清空入口同处"数据"区，让备份成为可见的前置选项。

弹窗会话约束

管理主入口是弹窗，因此弹窗的生命周期约束是产品行为的一部分，不是实现细节。

  • 弹窗在用户点击弹窗以外区域时被浏览器关闭，属于正常行为，不视为错误、不弹错误提示。
  • 所有结构性操作（归组、移出分组、分组排序、删除分组、标签重命名）在动作发生的当下立即持久化，不依赖"保存"按钮，避免关闭即丢失。
  • 编辑中的草稿（备注、标题、封面、新建分组名）在弹窗关闭前按草稿保存，下次打开时提示"是否继续上次未完成的编辑"，不静默丢弃。
  • 批量操作不因弹窗关闭而回滚：已完成条目保持结果，剩余条目在下次打开时给出"继续处理 N 条"的提示，用户可继续或放弃。
  • 需要连续拖拽、长时间停留或大量输入的任务，引导至"在标签页中打开"完成（UI-06），不在弹窗内提供只能在标签页完成的主流程。
  • 弹窗内不承载需要保持长连接或长时间后台等待的操作；此类操作应转为后台进行并在完成后以通知/角标告知。

关键异常汇总

场景期望行为
站点收藏请求失败不写入归组关系；提示失败原因并提供重试；重试成功后补写原选择的分组
未登录 / 登录态失效收藏入口不注入或提示登录；弹窗仍可浏览本地已存数据，但同步与重新收藏不可用
站点页面结构变化导致抓取失败收藏仍成功，元数据以占位值写入并提示"信息未抓全，可手动补全"；不得因抓取失败阻塞收藏
本地数据读取失败或损坏不静默重置；保留原始数据并提示导出/重置两个出口
同一条目多分组下同时被移除移除在最后一个分组上完成；若移除后无任何归属，自动进入未分组收集箱，而不是从插件消失
导入文件格式错误拒绝导入并提示错误位置；已存在的本地数据不发生部分写入
