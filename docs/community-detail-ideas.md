# 社区小细节建议清单（未实现）

工牌那三项（甩脱手 / 小鱼干 / 甩动音效）已经落地，这份清单是下一步可选的「小细节」，覆盖除工牌之外的社区使用位置。
原则：**不做功能，只做手感**。每项都不改变现有流程，失败或关掉开关都不影响主路径。

---

## 1. 发帖编辑 · 发布按钮「盖戳」

- **是什么**：点「发布」后，按钮不收成一个转圈，而是像盖章一样压下去：按钮轻微下沉 2px，同时一圈淡红墨迹从按下点扩散开、边缘带一点抖动，然后才进入提交状态。
- **用户在哪遇到**：发帖 / 编辑帖子页的底部发布按钮，是整条写作链路最后一下动作。
- **实现难度**：低。纯 CSS 动画 + 一个伪元素波纹，不需要改提交逻辑；只在禁用态而不是请求成功时才停住。
- **为什么有意思**：发布是不可逆动作，用户最紧张。一次「啪」的盖章比转圈更像「这事定了」，又不会拖慢流程（动画 320ms，提交并行跑）。

## 2. 浮层阅读 · 记住上次读到哪

- **是什么**：同一篇帖子再次从浮层打开时，直接回到上次的滚动位置；右侧边缘留一枚很淡的折角书签，点它可以一键回到顶部。
- **用户在哪遇到**：帖子浮层打开瞬间和关闭前，尤其是长帖看到一半被关掉、过一会儿又要翻回去的时候。
- **实现难度**：中。按帖子 id 在 `sessionStorage` 里存 `scrollTop`，恢复要等首屏渲染完（否则内容高度还没撑开）；折角书签需要一个滚动监听，注意和现有浮层滚动容器复用同一个 `scroll` 事件。
- **为什么有意思**：这是所有阅读器里最容易被忽略、但一用就回不去的小细节。它的成本只有一张键值表，收益是「不用再往上翻 30 屏」。

## 3. 搜索 · 历史记录变成「脚印小径」

- **是什么**：搜索框为空时的历史记录不再是竖排灰字列表，而是一串微微错开的猫爪印，从左上往右下延伸；鼠标划过去时对应爪印往下压一下再弹回。
- **用户在哪遇到**：搜索页的初始空状态——没输入任何字时看到的区域。
- **实现难度**：低。只是把历史列表的样式换成带随机偏移的圆形节点，交互是 transform + 点击保留原有逻辑；注意历史为空时退回一句普通提示。
- **为什么有意思**：空状态是「每天都会看到、但从来没人设计」的地方。把搜索历史变成一条走过来的路，比一排可删除的灰字更有记忆点，而且完全没有额外功能负担。

## 4. 收藏 · 卡片「飞进抽屉」

- **是什么**：点帖子卡片的收藏按钮时，按钮位置弹出一张缩小的帖子卡片剪影，沿一条弧线飞向收藏夹入口，落进去的瞬间入口图标轻轻下沉再回弹；失败则剪影原地碎成两半消失。
- **用户在哪遇到**：帖子列表 / 详情卡片的收藏按钮，以及顶栏的收藏入口。
- **实现难度**：中。用 FLIP 思路：克隆一个 60×40 的缩略卡片，`getBoundingClientRect` 算起止点，`transform` + 弧线用两段 cubic-bezier；需要避开「收藏成功但网络慢」的情况，动画结束前按钮保持 pending 态。
- **为什么有意思**：收藏这个动作本身没有任何视觉反馈，用户只能靠按钮变色确认。给「存起来」一个物理去处，比任何 toast 都好懂，而且它天然把用户的注意力引向收藏夹入口。

## 5. 通知 · 标记已读时「扫落」

- **是什么**：点「全部已读」时，未读条目按从上到下 30ms 的间隔依次向右上淡出并轻微缩小，像被扫帚扫走；红点数字滚动到 0 而不是瞬间消失。
- **用户在哪遇到**：站内通知浮层 / 通知页，尤其是积压了很多未读、一键清空的那一刻。
- **实现难度**：低。纯 CSS `animation-delay` 错峰 + 数字用一段简单的滚动计数；注意 `prefers-reduced-motion` 时直接设为 0 延迟无动画。
- **为什么有意思**：清空未读是个「爽点」，但现在的实现通常是整片瞬间消失，反而没有成就感。错峰扫落把批量操作变成一次小小的释放。

## 6. 起始页 · 空状态的一截窗台

- **是什么**：起始页没有内容时，不显示「暂无内容」四个字，而是一截窗台剪影：栏杆、一点光斑，鼠标停上去会有一条猫尾巴从右下角扫过再收回。
- **用户在哪遇到**：起始页浮层首次打开、或者过滤器把内容筛空的时候。
- **实现难度**：低到中。一张纯 CSS/SVG 剪影 + 一个 `:hover` 触发的尾巴路径动画；不需要图片资源，深色模式换一组颜色令牌即可。
- **为什么有意思**：空状态出现频率高、停留时间短，做重了会烦，做轻了刚好。尾巴扫一下这种「一次性的小动作」最合适——用户不会等第二次，但第一次会截图。

## 7. 设置页 · 右侧刻度尺

- **是什么**：设置页右边缘出现一条极细的竖向刻度，每个分区对应一个刻度点，滚动时当前分区的刻度加粗、旁边浮出分区名；点刻度直接跳过去。
- **用户在哪遇到**：设置页，尤其是「站点外观 / 刷帖体验优化 / 起始页浮层 / 搜索页 / 站内通知 / AI 功能 / PICKCAT Plus / 开放接口 / 关于」这九个区块之间来回找开关的时候。
- **实现难度**：低。`IntersectionObserver` 观察每个 `section.card`，滚动时改一个 `is-active` 类；点击直接 `scrollIntoView`，和左侧导航共用同一套锚点。
- **为什么有意思**：设置页已经很长，左侧导航在窄窗口会收起来。右侧刻度是一条不占位的「书的切口」，让长页面有了位置感，而且实现成本几乎只是一次观察器。

---

## 排序建议

如果只挑三项先做，按「成本 / 手感」比值推荐：**第 1 项（盖戳）→ 第 7 项（刻度尺）→ 第 5 项（扫落）**，三项都是纯前端表现层，互不依赖，也不碰任何接口。
第 2 项（记住读到哪）价值最高，但涉及浮层渲染时序，建议单独排期。
